# ABJ Odoo MCP

Standalone, self-hosted Odoo-to-MCP middleware. **No Odoo addon, restart, or module installation.** This release implements an admin login and dashboard, connection manager, MCP session and tool-call audit, version-specific native Odoo API adapters (17/18 RPC, 19 JSON-2), generated **read-only** search tools, and a local npm CLI that registers a single MCP gateway with installed clients.

## Requirements

- Node.js 20 or newer on the middleware server and each device running the local connector.
- Server-to-Odoo outbound HTTPS (HTTP only for loopback or explicitly trusted networks).
- Device-to-middleware access over LAN/VPN, or HTTPS via a protected reverse proxy.
- A native Odoo API key from the target user's Preferences; their login, database name, and URL. External API availability depends on Odoo hosting/plan.

## Server (internal VPS)

```bash
cd ABJ-ODOO-MCP
npm ci
npm install -g .
abj-odoo-mcp init     # enter a strong admin password; save the displayed MCP access token
abj-odoo-mcp serve    # defaults to 127.0.0.1:8090
```

Open `/admin` (redirects to `/login`) and sign in as `admin` with that password. The browser uses an HttpOnly, SameSite=Strict session cookie with an eight-hour lifetime. Add an Odoo URL, database, login, native API key, and comma-separated allowlisted models under **Connections**. Version defaults to auto-detection (JSON-2 for 19, then a verified RPC fallback for 17/18); manual selection remains available. The form probes Odoo using the native API **before** saving the connection. Once saved, each model exposes read-only `search` and `describe` MCP tools immediately. The MCP endpoint is `/mcp`.

**Sessions** displays native stateful MCP HTTP sessions. Revoke terminates the selected session, but a client with the server-wide bearer token can reconnect. **Tool logs** stores tool name, status, timestamp, and duration (not arguments, results, or Odoo API keys) in owner-only `activity.json`; the newest 250 sessions and 1,000 calls are retained. Restarts close recorded active sessions and invalidate all in-memory browser and MCP sessions. This is a single-instance local audit, not a multi-node database or tamper-proof audit log.

For Odoo 19, the API key itself determines the Odoo user; the login field is retained as connection metadata and is not an authentication parameter. Verify that the key belongs to the intended user. Replacing or removing a connection requires an explicit action in the UI.

For a trusted private network behind a TLS-terminating proxy, set `ABJ_HOST=0.0.0.0 ABJ_EXPOSE_HTTP=1 ABJ_COOKIE_SECURE=1`. The last flag forces Secure browser cookies behind TLS termination. Do not expose the built-in HTTP listener directly to the public internet. Restrict access to `/admin` at the proxy/VPN. `ABJ_PORT` and `ABJ_DATA_DIR` are optional. For an internal HTTP-only Odoo target, explicitly allowlist its hostname with `ABJ_HTTP_ODOO_HOSTS=internal-odoo.example`; never use this for public Odoo. Run under a dedicated OS user; back up its `~/.abj-odoo-mcp` directory securely. The server stores API keys encrypted with a key in its owner-only config file; for stronger at-rest isolation, use a dedicated secrets manager in production.

If a browser-based MCP client sends an `Origin` header from a different domain, explicitly allow it using `ABJ_ALLOWED_ORIGINS=https://trusted.example`. The default denies cross-origin requests.

The application caps inbound MCP requests at 1 MiB and Odoo API responses at 2 MiB, and temporarily rate-limits failed admin logins. It does not replace a properly secured reverse proxy and network access policy.

## Each local device

```bash
npm install -g /path/to/ABJ-ODOO-MCP
abj-odoo-mcp setup https://your-internal-mcp.example/mcp
```

Enter the MCP access token generated by `init`. Setup tests the remote MCP endpoint, shows installed clients and asks before registration. Currently supported: Codex CLI, Claude Code (user scope), and Antigravity CLI (`agy`). Existing registration with the same name is **not overwritten**. The installer registers a local stdio proxy, so no Odoo key or MCP token is written to client-specific configuration; the MCP token remains in `~/.abj-odoo-mcp/client.json` with owner-only permissions. Adding connections in the web UI requires no further installation; restart MCP clients to refresh their tool lists.

For local development on one machine, use `http://127.0.0.1:8090/mcp`. Run `npm test` to test the API adapters and a real MCP handshake against mock Odoo endpoints; tests do **not** connect to production.

## Initial-release boundaries

- Read-only `search_read` and `fields_get` tools only; no generic `execute_kw` tool, arbitrary method execution, `sudo`, writes, module operations, or addon-specific anomaly scanners.
- A single server-wide MCP token and admin login. Run one instance per trusted team; per-client keys/scopes, token rotation, durable multi-node audit storage, per-key rate limits, and multi-user roles are future work. See [Migration matrix](MIGRATION.md) for module parity and external-API constraints.
- Native API capabilities vary by Odoo version and plan. The 19 adapter uses JSON-2; 17/18 use the built-in JSON-RPC external API. Never describe these as universally available until a connection probe succeeds.
- No npm `postinstall` side effects. `setup` is an explicit, repeatable onboarding step that leaves unrelated MCP registrations untouched.
